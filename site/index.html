How to audit SQLite before and after a migration

A read-only workflow for schema, NULLs, storage types, foreign keys and specified duplicate keys, with offline HTML/JSON output and an optional coding-agent skill.

Exact counts, stated limits

Scans are read-only and run in one snapshot transaction. Full scans can be expensive on large databases. Row-count changes, more NULLs and mixed storage types are observations; they do not automatically fail the regression gate.

Reports omit record payloads and duplicate-key values, but include schema SQL and diagnostic metadata. Review those before sharing your own report. The hosted demo contains synthetic fixtures only.
